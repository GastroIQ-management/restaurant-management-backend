## Pull request description
**Store each user's preferred language and send emails in it**

Users can now choose the language of their emails (English, Portuguese or French). Verification,
password reset and invitation emails follow that choice. Implements backlog item
`backlog/improvements/2026-10-20-store-user-preferred-language.md` (the deletion of the item is committed separately).

**Identity**
- New nullable `users.preferred_language` column (migration `AddUserPreferredLanguage`).
- New `PUT api/users/me/language` (signed in; the user comes only from the token). Accepts
  `en`, `pt` or `fr` and returns 204, or 400 with a translated message. Missing, inactive or
  unverified users get 401.
- The verification and reset background processors use the stored language, or English when none
  is stored. Registration uses the request's language.
- An invitation to an existing account uses that account's language, otherwise the inviter's
  request language (now including French). A French invitation email is added.

**Shared**
- Shared contract change: `IEmailService.SendVerificationEmailAsync` and `SendPasswordResetEmailAsync`
  take a `language` parameter. Any value other than `en`, `pt` or `fr` is answered in English.
- Portuguese and French verification and reset emails with translated subjects (new
  `LocalizedCodeEmail` helper).
- New message `LanguageUnsupported_ValidationError` in en/pt/fr.

**Risk and flags**
- Shared contract change (approved). Migration adds a nullable column, with no backfill.
- PT/FR email text was written without native review.
- Known gaps: registration and invitation sign-up do not store the language yet (review items #1 and #2).

**Security matrices:** identity R16, RS12, P29, T134–T141, D34; shared SH24 (updated), SH47–SH50.
