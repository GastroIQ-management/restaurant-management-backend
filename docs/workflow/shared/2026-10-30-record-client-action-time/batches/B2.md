## T3 — Business day of a location through a Shared contract
| Field | Value |
|---|---|
| Expected context | `IBusinessDayCalculator` (Organization) already computes a business day from a UTC moment, an IANA (Internet Assigned Numbers Authority) time zone and a cutoff. Nothing outside the module can reach it. `Location.TimeZone` holds the zone; `OrganizationSettings.BusinessDayCutoff` holds the cutoff (04:00 by default). Follow `OrganizationLookup`: implemented in `Services/`, registered by the Web host. Reads go through the tenant query filter (no `IgnoreQueryFilters`) and use no tracking, since the call can run inside a save of the same context |
| Expected result | `ILocationBusinessDay` returns the business day of a location of the token organization for a moment, using its time zone and the organization's cutoff. It returns null for an unknown location or another organization's location |
| Outcome | #3: unit tests on SQLite with an action at 23:30 local that is already the next day in UTC return the local date, for a location in `America/Sao_Paulo` and one in `America/Toronto` |
| Files | add `src/RestaurantManagement.Modules.Organization/Services/LocationBusinessDay.cs` · change `src/RestaurantManagement.Web/Program.cs` (registration) · change `docs/security/organization-matrix.md` |
| Modules | Organization, Web (host wiring only) |
| Flags | Security: reads location data; must stay inside the token organization |
| DoD | Tests written and passing · unit tests in `tests/RestaurantManagement.Modules.Organization.Tests/` · cross-tenant test: another organization's location returns null (not found) · no role rejection test: the spec changes no access rule · `docs/security/organization-matrix.md` rows added and ✅ with their tests; `python3 .claude/scripts/check-security-matrices.py` passes |
| Depends on | T2 |
