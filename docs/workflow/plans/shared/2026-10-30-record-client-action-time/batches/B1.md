## T1 — Check the device-time headers on signed-in writes
| Field | Value |
|---|---|
| Expected context | Writes carry no device time today. Follow `IdempotencyKeyFilter`: a global controller filter that applies only to signed-in writes (POST, PUT, PATCH, DELETE with `[Authorize]` and no `[AllowAnonymous]`). Register it in `Program.cs` right after `IdempotencyKeyFilter`, so the key lookup answers a replay first and a refusal frees the key. Refusals throw `BusinessException` with a code from the Shared catalog and a translated title. The server receive time is read once from the injected `TimeProvider` |
| Expected result | `X-Client-Action-Time` (when the user acted) and `X-Client-Sent-At` (the device clock at send time) are both required. Each is one value in RFC 3339 format with an offset (`Z` or `±hh:mm`), with a length limit. Missing: 400 `client_time.required`. Unreadable, several values, no offset or too long: 400 `client_time.invalid`. Clock error = sent-at minus received time (positive means the device is fast). Corrected time = action time minus clock error. Corrected time more than 5 minutes after received time: 422 `client_time.in_future`. More than 7 days before it: 422 `client_time.too_old`. Every refusal runs nothing and stores nothing. Accepted values go to a request-scoped holder: action time (UTC, Coordinated Universal Time), its offset, corrected time, clock error and received time. Anonymous writes and reads are unchanged |
| Outcome | #2 (clock error computed), #4, #5, #6: unit tests on parsing, clock error and both bounds at 4 and 6 minutes and at 7 days ± 1 minute; endpoint tests on a Menu create show 400 or 422 and no row stored |

## T2 — Stamp the times on every saved record
| Field | Value |
|---|---|
| Expected context | `AuditSaveChangesInterceptor` stamps `CreatedAt` and `UpdatedAt` on every `BaseEntity`. Add a separate interceptor (one responsibility) in `Shared/Data/ClientTime/`, attached to all four contexts (Identity, Menu, Organization, audit log). No entity derives from `LocationEntity` yet. The business day needs the location's time zone and cutoff, owned by Organization. Add a small Shared contract `ILocationBusinessDay` (location ID and moment in, date or null out). Resolve it lazily at save time, and only when a location record is in the save: the Organization context also carries this interceptor, so eager injection is a circular dependency |
| Expected result | New `BaseEntity` columns, all nullable: device action time (UTC), its offset in minutes, corrected action time, clock error and received time. `LocationEntity` gets a nullable business day (date). When the holder has values: added and modified rows get the five times; an added location row also gets its business day from the contract, using the corrected time. An update never changes the business day. When the holder is empty, nothing is stamped. A synchronous save with a location row fails loudly instead of skipping the business day. A replay (idempotency) never saves, so the stored times stay. Audit log rows are stamped like every other row |
| Outcome | #1, #2 (stored), #3 (location row gets the contract's date), #7: interceptor unit tests on a test context; endpoint tests on a Menu create (times stored, received time later than the 5-hour-old action time; 10-minute-fast clock stored; same key replayed later leaves times unchanged) |
