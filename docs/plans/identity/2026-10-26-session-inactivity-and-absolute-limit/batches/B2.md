**Module:** Identity   **Depends on:** T1 (B1)   **Tasks:** T2

## T2 — Refresh tokens keep the login time; expiry from both limits

**Outcome:** #1, #2, #5, #6   **Priority:** P1

### Context
- New `RefreshToken.SessionStartedAt` column holds the login time:
  - `IssueAsync` (login) sets it to now
  - `ReplaceAsync` (rotation) copies it from the old token
- Every new token expires at the earlier of now + `SessionInactivityDays` and `SessionStartedAt` + `SessionAbsoluteDays`. A refresh therefore never moves the session end.
- `RotateAsync` refuses a token when it has expired, or when now ≥ `SessionStartedAt` + `SessionAbsoluteDays`. This second check covers a lowered limit.
- The refusal is the usual null, giving 401 `InvalidOrExpiredToken`. It runs before the reuse check, like expiry today, so nothing is revoked (F2).
- The cookie expiry already follows the token's `ExpiresAt`, so it needs no change.
- Remove `RefreshTokenExpireDays` from `JwtOptions` and from `appsettings.json`, with no fallback.
- Migration: follow `.claude/skills/ef-migration/SKILL.md`. Make the column required with no backfill: the table holds no real data before launch.
- Cleanup (T9) is unchanged. It deletes tokens 30 days after they expire, so a rotated token stays stored while it can still trigger reuse detection.
- Services read `DateTime.UtcNow`. Tests seed rows with past `CreatedAt`, `SessionStartedAt` and `ExpiresAt` values.
