## T1 — Session limit settings and startup checks

**Outcome:** #4, #5 (T17 and the startup rows)   **Priority:** P1

### Context
- `JwtOptions` (Shared) holds `RefreshTokenExpireDays` (30), and today it sets every new token's expiry, rotations included.
- This task adds two settings beside it: `SessionInactivityDays` (default 7) and `SessionAbsoluteDays` (default 30).
- `RefreshTokenExpireDays` stays until T2 switches the code over and removes it. Keeping it lets this commit build.
- `JwtOptionsValidator` runs at startup (`ValidateOnStart` in `Program.cs`). It must refuse:
  - either setting at 0 or below
  - `SessionInactivityDays` greater than `SessionAbsoluteDays`

  Each failure message names the setting, like the existing `Jwt:ExpireMinutes` message. Equal values are accepted.
- Shipped values in `appsettings.json` under `Jwt`: `SessionInactivityDays: 7`, `SessionAbsoluteDays: 30`.
