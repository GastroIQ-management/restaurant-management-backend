## T2 — Menu create takes the client's ID
| Field | Value |
|---|---|
| Expected context | `POST api/v1/menus/create`: `CreateMenuRequest` has no `Id`; `MenuService.CreateMenuAsync` sets `Id = Guid.NewGuid()` (line 61) inside a transaction, then adds location links. Required-ID pattern to copy: `[RequiredId]` + `[JsonConverter(typeof(LenientGuidConverter))]` on `CreateMenuCategoryRequest.MenuId` (Shared row SH20). Access is checked before the save (Menus Manage at the named locations, or everywhere), so a caller without the right never learns whether an ID is taken. Existing tests that post this create send no `id` and get one in step 3 |
| Expected result | `id` is required: missing, null, malformed or empty answers 400 on the field, translated. The menu is stored under that ID and the response `id` equals it. A primary key clash (same or another organization) answers 409 `id.already_used`, rolls the transaction back and stores no menu and no location link. The menu's organization is the token's `org_id`; an `organizationId` in the body is ignored |
| Outcome | #1–#6; verified by endpoint tests in `tests/RestaurantManagement.Web.Tests/Menu/` (PostgreSQL) and an OpenAPI (API description document) check of `/swagger/v1/swagger.json` |
| Files | `change` `src/RestaurantManagement.Modules.Menu/Models/CreateMenuRequest.cs` · `change` `src/RestaurantManagement.Modules.Menu/Services/MenuService.cs` · `change` `docs/security/menu-matrix.md` |
| Modules | Menu |
| Flags | Security: client-chosen primary key on a tenant create |
| DoD | Tests written and passing · empty UUID 400 · same-organization reuse 409 · cross-tenant: another organization's menu ID answers the same status, title and code as the same-organization 409, the body holds no ID or name of that organization, and its menu is unchanged · an `organizationId` of another organization in the body is ignored (row read back in the token organization) · a member without Menus Manage sending a taken ID gets 403, not 409 · OpenAPI shows `id` (uuid, required) on `CreateMenuRequest` · `docs/security/menu-matrix.md` rows added or changed and ✅ with their tests; `python3 .claude/scripts/check-security-matrices.py` passes |
| Depends on | T1 |
| Uses from dependency | `ErrorCodes.IdAlreadyUsed`, `IdAlreadyUsed` message, primary key violation check |
| Provides | — |

**Implementation guide** (written by the tester)
| Step | What to do |
|---|---|
| 1 | In `CreateMenuRequest` put `[RequiredId(ErrorMessage = "RequiredAttribute_ValidationError")]` and `[JsonConverter(typeof(LenientGuidConverter))]` on the existing `Id` property (scenario #6). |
| 2 | In `MenuService.CreateMenuAsync` use `Id = request.Id` instead of `Guid.NewGuid()`. |
| 3 | Around the first `SaveChangesAsync` catch `DbUpdateException` when `PrimaryKeyViolation.Matches(ex)` and throw `BusinessException(ErrorCodes.IdAlreadyUsed, localizer["IdAlreadyUsed"])`; dispose the transaction so nothing is stored (scenarios #7, #8). |
