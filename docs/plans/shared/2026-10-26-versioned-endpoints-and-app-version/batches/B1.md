## T1 — Writes require the app version header
| Field | Value |
|---|---|
| Expected context | No request carries the app version. Shared middlewares live in `src/RestaurantManagement.Shared/Middleware/` (`ExceptionHandlingMiddleware`, `LocationAccessMiddleware`) and answer refusals through `ProblemResponse` with a code from `ErrorCodes` and a title from `SharedResource` (English, Portuguese, French). Shared already reports to Sentry. CORS (Cross-Origin Resource Sharing) allows any header. Pipeline order is in `src/RestaurantManagement.Web/Program.cs` |
| Expected result | A POST, PUT, PATCH or DELETE without `X-App-Version` answers 400 `app_version.required`; a value that is not a semantic version (`major.minor.patch`, optional `-`/`+` suffix) or is over 32 characters answers 400 `app_version.invalid`; both as Problem Details with a translated title. GET, HEAD and OPTIONS (CORS preflight) pass without it. The check runs after CORS and before sign-in, so an anonymous and a signed-in caller get the same answer, and a browser can read it. A valid value is set as the `app_version` tag on Sentry events of the request; it is never stored or used for access. The header name is a public constant T7 reads. The tester fixes the exact code names in `scenarios.md` |
| Outcome | #2: write without the header, with a malformed and with a 33-character value each answer 400 with their code on a public (login) and a signed-in endpoint; a read without it answers as before; a write with a valid value reaches the endpoint |
| Files | `add` `src/RestaurantManagement.Shared/Middleware/AppVersionMiddleware.cs` · `change` `src/RestaurantManagement.Shared/Utils/Exceptions/ErrorCodes.cs` · `change` `src/RestaurantManagement.Shared/Localization/SharedResource.resx`, `.pt.resx`, `.fr.resx` · `change` `src/RestaurantManagement.Web/Program.cs` (register it) · `change` `docs/security/shared-matrix.md` |
| Modules | Shared (one registration line in Web) |
| Flags | Security: new client-supplied header, bounded in length and format, never used for access; public sign-in endpoints also refuse a write without it |
| DoD | Tests written and passing: unit in `tests/RestaurantManagement.Shared.Tests/`, endpoint in `tests/RestaurantManagement.Web.Tests/Shared/` · every Web.Tests factory client (`TenantApiFactory`, `AuthApiFactory` and any other) sends a valid `X-App-Version` by default, so existing tests keep passing; refusal tests remove it · `docs/security/shared-matrix.md` new rows (missing, malformed, too long, read without it, same answer signed in or not) ✅ with their tests; `python3 .claude/scripts/check-security-matrices.py` passes · build passes |
| Depends on | — |
| Uses from dependency | — |
| Provides | The header name constant and the two codes (T7) |
