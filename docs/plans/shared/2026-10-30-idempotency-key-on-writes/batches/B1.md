## T2 — Shared transaction a service can join, with an undo step when it does not commit
| Field | Value |
|---|---|
| Expected context | Some services open their own transaction with `Database.BeginTransactionAsync()`. EF Core refuses a second transaction on a context that already has one. Signed-in ones: `MenuService.CreateMenuAsync` and `OrganizationService.CreateOrganizationAsync` (`PasswordChangeService` serves an endpoint that ignores the key, T7). `CreateOrganizationAsync` sets up the Owner in Identity before its commit, and revokes the Owner when the commit fails. Module rule: no transaction spans two modules' contexts |
| Expected result | One Shared helper begins a transaction on a context, or joins the one already open on that same context. Owned: commit and rollback work as today. Joined: commit and rollback are left to the code that opened the transaction, and the joined work is kept or discarded with it. A step registered on the handle (an undo of a change made in another module) runs once when the transaction ends without a commit (rollback or failed commit), whoever opened it. The helper never touches another context's transaction |

## T3 — Shared write filter: check, reserve, replay, save with the write
| Field | Value |
|---|---|
| Expected context | Writes reach controllers after `AppVersionMiddleware`, authentication, authorization and `LocationAccessMiddleware`. The user and organization come only from the token (`ICurrentUser`). Refusals are `BusinessException`s answered by `ExceptionHandlingMiddleware`. `[ApiController]` answers an invalid body with 400. A filter is needed, not a middleware, because only the matched action tells which module's context holds the key. Audit entries (`IAuditLog`) and emails are saved or sent on their own, and are not undone with the write (unchanged) |
| Expected result | Applies only to a POST, PUT, PATCH or DELETE on an action that requires sign-in (no `[AllowAnonymous]`), by a signed-in user who sends `Idempotency-Key`, when the module has a key store and the action is not marked to ignore keys. Any other request runs as today. (1) A key that is not a UUID (Universally Unique Identifier) → 400 `idempotency_key.invalid`, and nothing runs. (2) Request hash: SHA-256 (Secure Hash Algorithm, 256-bit) of the method, path with query, `X-Location-Id` and raw body. (3) A stored row for this user, organization and key: expired or abandoned → treated as new; another hash → 422 `idempotency_key.reused`; in progress → 409 `request.in_progress`; completed → its stored status, content type, body and `Location` are answered, and the action does not run. (4) A new key is reserved and saved at once. Then the action and its result run inside the T2 transaction on the module's context, and the answer is held back. A success (2xx) answer completes the key in that transaction, commits, and is then sent. Any other answer, an exception or a failed commit rolls back, releases the key and answers the original error. A marker lets an action ignore keys |
| Outcome | #1–#9. Unit tests in `tests/RestaurantManagement.Shared.Tests/`. End-to-end PostgreSQL tests in `tests/RestaurantManagement.Web.Tests/Shared/` through the Menu create endpoint (green once T5 wires Menu) |
| Files | `add` `src/RestaurantManagement.Shared/Services/Idempotency/` (write filter, request hash, ignore-keys marker) · `change` `docs/security/shared-matrix.md` |
| Modules | Shared |
| Flags | Security: a replay is answered before the module's access checks, only to the same user in the same organization; a write with a key runs in one transaction |
| DoD | Tests written and passing · same key and request twice: one menu, identical status and body (#1) · changed body, and changed target: 422 both times, nothing stored (#2) · a key still in progress: 409, one menu (#3) · cross-tenant: the same key from another user, and from a user of another organization, runs their own write and never returns the first answer (#4) · no key: as today (#5) · a key that is not a UUID: 400, nothing runs (#6) · failed validation, then a corrected request with the same key: it runs (#7) · forced failure while completing the key: no menu (#8) · key older than retention: runs as new, old row removed (#9) · anonymous write, read, and marked action with a key: as today · the spec disallows no role: a member without Menus Manage gets 403 with a key, and nothing is stored · `docs/security/shared-matrix.md` rows added or changed and ✅ with their tests; `python3 .claude/scripts/check-security-matrices.py` passes |
