## T3 — Host answers as Problem Details
| Field | Value |
|---|---|
| Expected context | The Web host writes its own error bodies. In `Program.cs`, the JWT (JSON Web Token) events answer `{ message }`: 401 "invalid token" (forged or expired, never saying why), 401 "unauthorized" (no token), 403 "access denied" (`PermissionAuthorizationHandler` leaves a refused requirement unmet). The rate limiter answers 429 `{ message }` with `Retry-After`, exposed to allowed origins by CORS (Cross-Origin Resource Sharing). `LocalizedValidationTitleExtensions` localizes the validation 400 title but adds no code. With `[ApiController]`, bodiless results such as `Unauthorized()` in the Identity controllers become Problem Details with an English title and no code; unknown routes and 405 answer an empty body |
| Expected result | Every answer the host makes is Problem Details (`application/problem+json`) with a code and a localized title, written by the Shared writer or the framework Problem Details service: invalid or expired token `auth.invalid_token`; no token `auth.unauthorized`; refused permission `access.denied`; rate limit `rate_limit.exceeded`, `Retry-After` kept; validation `validation.failed` with the field `errors` kept. A bodiless error result, an unknown route, 405 and 415 get the fallback code and title of their status (T1). Statuses unchanged. The setup lives in one hosting extension that `Program.cs` calls |
